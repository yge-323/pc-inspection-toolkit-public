# 产品需求基线（唯一方向）

日期：2026-10-12。状态：**已确认的产品需求**；实现版本目标 `0.3.0-landable`（可本机一键 + U 盘 + 堡垒机粘贴落地）。

## 一句话

一套**通用、便携、准备 GitHub 开源**的系统巡检与 AI 辅助分析工具：  
任意受支持设备 → 授权采集 → 脱敏证据 → **规则检查 + AI 分析** → 中文问题与整改报告 → 人工处理 → 复查。

PC 验机、办公电脑巡检、内网老旧物理服务器巡检，是**同一产品的不同适用对象**，不是三条产品线。  
本地运行、U 盘、SSH、SecureCRT / 4A 粘贴，是**同一产品的不同接入方式**，不是互相取代。  
AI 是**所有采集结果的共同分析环节**，不是单独的「场景 C」。

## 固定需求清单

1. **产品定位**  
   面向普通用户与运维人员；免费起步、可开源；不绑定作者个人电脑、公司、路径或环境。

2. **PC 检查**  
   覆盖常见新旧 Windows PC（二手本、台式机、办公机）。检查硬件与异常、磁盘健康、软件清单、常见安全软件/远控残留、可疑账号、权限、启动项、计划任务、服务、端口、安全配置。  
   **不能只凭软件名称判定恶意。**

3. **服务器检查**  
   实体物理机为主，虚拟机兼容。重点场景是**内网、隔离网、长期运行的老旧服务器**。不以云厂商控制台为前提（云上已有厂商工具，本工具价值更小）。

4. **操作系统覆盖**  
   主体：Windows 客户端、Windows Server、RHEL、CentOS。  
   专项：旧 AIX 等传统 Unix。  
   按真实能力与版本矩阵逐步实现，禁止声称「一个脚本无差别扫遍一切」。生命周期资料用厂商公开文档建立能力表。

5. **物理硬件检查**  
   在系统、权限与厂商工具允许时检查 SMART、RAID、磁盘故障线索、温度、电源、风扇、硬件事件等。  
   **取不到证据就标未知，禁止伪装成健康通过。**

6. **采集方式（统一入口）**  
   - 本机直接运行  
   - U 盘离线脚本（目标端尽量零安装）  
   - SSH  
   - SecureCRT / 4A / 堡垒机授权终端：执行固定只读命令，复制输出（粘贴模式）  
   不绕过客户平台的命令控制与审计。

7. **采集内容**  
   通用：系统信息、资源、账户摘要、进程、服务、端口、启动项、安全设置、系统与应用版本。  
   按需专项：日志、Tomcat、WAS、Nginx、Redis、Oracle、MySQL 等。

8. **AI 是共同分析环节**  
   所有来源的证据都能进入规则引擎与 AI。  
   AI 解释硬件风险、异常软件、系统问题、应用故障：证据依据、可能原因、下一步排查、整改建议。  
   可选本地 Ollama，或**获授权**的云端模型；无网时先存证据后分析。  
   AI **不自动改系统、不覆盖确定性规则结论**；报告中必须区分「已确认事实 / 规则推断 / AI 假设」。

9. **结果与整改**  
   每条问题含：事实、推断层级、依据、适用版本、影响、人工步骤、回滚、复查。  
   输出中文 HTML / Markdown / CSV 等。  
   **不自动删除软件、不改策略、不自动修复。**

10. **通用性与开源**  
    配置、端口、路径、模型、规则、白名单不得写死在个人环境。  
    提供可复现构建与测试、许可证、说明与示例报告。  
    公开前清理历史中的个人路径、账号、客户信息与真实采集数据（必要时用干净公开仓库重新开始，而不是把当前私有库直接 Public）。

## 明确不做

- 漏洞利用、弱口令爆破、未授权扫描  
- 绕过 4A / 堡垒机策略  
- 自动加固或常驻 Agent 平台  
- 把云厂商运维控制台当作主战场

## 与现有代码的关系（处置结论）

**保留并演进（不要删库）**

| 资产 | 理由 |
|---|---|
| `evidence/` 证据包契约 | 离线交换的核心，开源可信基础 |
| `platforms/` 原生采集（含 `inspect.ps1`） | 零安装/老系统方向正确 |
| `analyzers/` + `rules/` | 规则分析内核；监听知识等继续扩 |
| `reports/`、`compare`、桌面向导 | 用户闭环已可用 |
| `tests/` + GitHub Actions | 跨平台回归底线 |
| 技术设计草稿：Finding / severity / vendor / Windows 规则 | 仍有参考价值 |

**本轮已删除（方向噪音 / 开源污染）**

- `docs/execution-log-*.md`、`docs/task-trace-*`（含本机路径与个人环境）  
- 互相打架的旧计划：`v0.3-plan`、`v0.4-html-report-plan`、`restart-design-and-execution-plan`、`v0.3-redesign-and-luna-execution-plan`、`project-working-rules`  
- Legacy PowerShell 链：`run-inspection.*`、`work/windows-inspection.ps1`（不再作为入口，也不再维护）

**待新增（下一阶段开发，不在本文档空转）**

- 统一事实模型（PC / 服务器共用）  
- Linux 安全摘要采集与目标端配置字段抽取  
- 4A / SecureCRT 粘贴导入  
- 硬件 SMART/RAID 等「可取得则采、否则 UNKNOWN」  
- 规则包 + 整改剧本扩面；AI 分析接口产品化（规则结论仍优先）  
- 开源前：许可证、干净历史、脱敏示例报告

## 统一流程（给实现与 Agent 用）

```text
受支持设备（PC / 办公机 / 内网老服务器）
        │
   授权采集（本机 | U盘 | SSH | 堡垒机粘贴）
        │
   脱敏 EvidenceBundle
        │
   规则引擎（确定性） ──┐
                        ├──→ 中文报告 / 整改工单 / 复查
   AI 分析（可选、解释性）─┘
        │
   人工处理 → 再采集比较
```

任何后续计划若重新拆成「只做 PC」或「只做 AI 场景」而丢掉其他入口，视为偏离本基线。
